# Decision 0001: v0.4 Analysis Scope

- Status: Accepted
- Date: 2026-08-22
- Release target: v0.4.0

## Context

`next-secure-check` currently combines deterministic rules, lightweight path context, and syntax-level AST checks. This keeps normal scans fast and explainable, but it cannot reliably follow values through wrappers, aliases, or multiple files. Real-world repository scans showed that adding more broad regexes would increase noise faster than it would improve signal.

Local measurements reported for this decision put a warm syntax scan around a few hundred milliseconds, while loading a TypeScript `Program` and `TypeChecker` took roughly 1.7 to 5.5 seconds depending on the project configuration. Those measurements are directional, not a universal benchmark, but they make a default TypeChecker dependency a poor first step for v0.4.

## Decision

v0.4 will use a bounded, syntax-only source-to-sink layer on top of the existing AST utilities. The first production pilot will target `injection/command-exec` and will be limited to same-function, local-scope flow.

The supported flow will initially cover direct expressions, direct assignments, a short identifier alias chain, and explicit same-function guards. Reassignment, mutation, closures, callbacks, cross-function flow, cross-file flow, call graphs, full CFG analysis, and dynamic resolution are non-goals.

TypeChecker/Program analysis will be an opt-in, measured spike only. It will not become the default scanner path in v0.4.

## Initial Facts

Candidate sources:

- `request.json()`
- `request.formData()`
- `req.body` and `req.query`
- `searchParams.get(...)`
- route parameters

Candidate command sinks:

- `exec(...)`
- `execSync(...)`
- `spawn(...)` or `spawnSync(...)` when `shell: true` is explicit

Guards are rule-specific. SQL parameterization, recognized HTML sanitizers, and command allowlists must be represented by separate facts rather than one universal sanitized flag.

## Acceptance Criteria

The pilot must include at least 30 representative fixtures and show either five confirmed false-positive reductions or five correct additional findings, with no critical regressions. It must document intentional false negatives, preserve deterministic finding IDs and SARIF fingerprints, and keep syntax-mode performance within the existing budget.

The TypeChecker experiment must be measured separately. It should stay under 2 seconds on a small project and 8 seconds on a medium monorepo, and it must fall back to syntax mode when project configuration cannot be loaded safely.

## Consequences

This approach intentionally leaves some advanced data-flow findings for later. In return, v0.4 can improve the highest-value rule without forcing every scan to load a project graph or requiring a broad rewrite of the 20-rule engine.
