# Decision 0006: Bounded SSRF Review Signal

- Status: Accepted for the unreleased v0.6 development line
- Scope: Issue #33
- Published v0.5 effect: None

## Decision

Add one separately identified rule, `ssrf/unvalidated-outbound-url`, for a
server-side request-derived URL that reaches a small, documented outbound HTTP
sink without a visible destination guard. Keep the rule syntax-first and
bounded. It is a review signal, not proof of exploitability.

The rule is implemented as a policy module over the existing bounded-flow
walker. It does not introduce a second generic traversal engine or make network
requests. `AnalysisFacts` keeps the result on the existing per-file parse/cache
path so other rules do not parse the same file again.

## Supported Boundary

Sources are limited to URL-like fields from request/query/route/form/body
inputs, including `request.url`, `request.json()`, `request.formData()`,
`request.nextUrl.searchParams.get(...)`, `req.query`/`req.body`, route params,
and `searchParams.get(...)`. Direct assignments and at most two local aliases
are followed inside the same supported server function.

Sinks are the global `fetch` function plus recognized `axios`/`got` bindings and
their `.get` methods. The allowlist is exact and intentionally does not discover
arbitrary HTTP clients or dynamic properties.

Visible static host/origin membership/equality, same-file URL host checks, and
recognized early-exit safe/private-network helpers can suppress a finding. URL
construction without a validation relationship does not suppress it.

## Stop Conditions

Stop at client components, module scope, non-exported helper entry points,
unknown wrappers, dynamic sinks/properties, reassignment/mutation, unsupported
request fields, aliases beyond two hops, cross-file flow, cross-function source
to sink flow, network/DNS work, and runtime exploit confirmation.

## Compatibility and Evidence

The v0.5.0 published package remains a 20-rule baseline. This rule is exposed
only by the unreleased main development line, bringing that line to 23 rules
after the existing Server Action and redirect slices. Existing rule IDs, CLI
flags, reporter formats, SARIF identity/fingerprints, no-code-execution, and
privacy contracts remain unchanged.

Each finding retains the existing line/column and reporter metadata and adds a
bounded `evidencePath` such as `request.query -> url -> target`. Evidence paths
contain syntax labels only; raw URL values, tokens, credentials, and local paths
are not stored.

## Consequences

The signal gives Next.js teams a fast, explainable review point for common proxy
patterns while deliberately missing custom clients and interprocedural flows.
The quality bar is precision, clear boundaries, deterministic output, privacy,
and acceptable performance—not an expanding taint engine or rule count.
