# Decision 0007: v0.6 Cookie and Next.js Configuration Hardening Signals

Date: 2026-08-31

Status: Accepted for the bounded #34 implementation

Issue: [#34](https://github.com/SetraTheXX/next-secure-check/issues/34)

Published v0.5 effect: None

## Decision

Add `auth/session-cookie-without-security-flags` and
`config/next-image-domains` to the unreleased v0.6 development line, and
refine `headers/missing-security-headers` with syntax-aware evidence. These
signals are deterministic review points, not universal claims about runtime
cookie behavior, deployment headers, or exploitability.

## Recognized cookie boundary

The cookie signal recognizes auth/session-like names through:

- `cookies().set(...)` and a same-function `await cookies()` store alias;
- bounded `response.cookies.set(...)` forms;
- Pages Router `res.setHeader("Set-Cookie", serialize(...))` and
  `serializeCookie(...)` forms.

The name vocabulary is deliberately token-based (`session`, `auth`, `token`,
`access`, `refresh`, `jwt`, and related exact segments), so ordinary names such
as `accessibility` and `tokenizer` do not match. The analyzer records visible
`httpOnly`, `secure`, and `sameSite` states. Partial static omissions remain
reviewable at LOW when only one flag is missing; dynamic options and broader
missing states remain explicitly bounded and privacy-safe.

Cookie names, values, tokens, credentials, and option expressions are never
copied into finding evidence. Custom wrappers/serializers, dynamic names,
cross-file or cross-function flow, runtime TLS/browser behavior, and
unsupported cookie APIs are outside the boundary.

## Recognized configuration boundary

The existing header rule recognizes static header names in `headers()` methods
or properties in `next.config.cjs`, `.js`, `.mjs`, and `.ts` files. It also
recognizes static `set`/`append` calls on `response.headers` inside named
`middleware` or `proxy` JavaScript/TypeScript entry functions. Content Security
Policy contributes frame protection only when the bounded syntax contains a
`frame-ancestors` signal; `X-Frame-Options` is the direct alternative.

Dynamic names or values are described as unevaluated when another required
header is missing. If all required names are statically present, the existing
missing-header rule does not claim that a header is missing; runtime and
hosting behavior remain outside the result.

`config/next-image-domains` recognizes a non-empty static string array under
`images.domains` in the same supported Next.js config extensions. It does not
flag `images.remotePatterns`, empty arrays, dynamic values, or unrelated
objects. Configured host values are omitted from evidence.

## Compatibility and stop conditions

The published v0.5.0 package remains a 20-rule baseline. The v0.6 development
line now contains 25 rules. Existing rule IDs, CLI flags, report formats,
finding identity, deterministic SARIF behavior, no-code-execution behavior,
and public-output privacy remain unchanged. No npm package, release tag, or
Action consumption tag is moved by this slice.

The analyzer does not evaluate full Next.js config objects, dynamic framework
resolution, complete CSP correctness, reverse-proxy configuration, browser
enforcement, runtime TLS, universal cookie semantics, or cross-file framework
graphs.
